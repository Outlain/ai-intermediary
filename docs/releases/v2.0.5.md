# AI Intermediary v2.0.5

## Frigate context rescue alongside idle ComfyUI

- Fixes repeated `rescue_gpu_busy` deferrals when ComfyUI has finished cleanup
  but retains a small, verified GPU allocation. Rescue rechecks the existing
  worker unload proof, empty queue, allocator limit, host-confirmed ownership
  and stable physical telemetry under the shared inference gate.
- Reuses existing media idle-activity and residual-memory limits. No new
  settings, raised limits, blanket Python exemption or automatic service stop
  is introduced. Unknown processes, active media, changed proofs, stale
  telemetry and inadequate RAM/VRAM still block dispatch.
- A known, cached Ollama model can remain loaded during these checks. Its
  reported GPU allocation is excluded from residual-memory accounting; unknown
  or inconsistent accounting fails closed. The configured context cap and
  one-enlarged-attempt limit are unchanged.
- The dashboard now says **Request selected** while pre-dispatch checks are
  pending, and **Model state refreshed** for bookkeeping reconciliation. Neither
  message claims a generation or physical model load/unload happened.

## Upgrade from v2.0.4

Only the intermediary container needs updating to
`ghcr.io/outlain/ai-intermediary:v2.0.5`. Existing v2.0.4 host and ComfyUI bridge
files are unchanged. Preserve your Compose overrides, state volumes, credentials,
models and media. Pause inference and allow active generation to finish before
recreating the intermediary. Resume separately after verifying the new version
and backend readiness. Do not clear a pre-existing recovery lock to perform this
update.

This is not a RAM/OOM fix and does not claim to resolve unrelated Odysseus HTTP
502 errors. It does not restart ComfyUI or Ollama, reset the GPU, replay finished
generation, clear recovery state, or automatically resume a manual pause.
