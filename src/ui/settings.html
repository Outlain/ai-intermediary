Sources & dedicated ports

One Ollama backend, one inference at a time. Larger priority numbers run first; equal priorities use arrival order. Identification: dedicated port → enabled client header → IP/subnet → legacy model mapping → default source. Headers and ports are routing hints, not authentication.

Adding misc does not change your current default source. Map Odysseus first, then select misc under Scheduler if desired. Disable a source to stop inference without removing its identity.

Docker port publication

Applying a listener port starts it inside the container after a safe restart. Docker must also publish it. Add the lines below under the existing ollama-scheduler service in your Compose file, preserving your current ports, then recreate that service. Host port reachability is not automatically verified. Do not forward clients directly to Ollama.


          
Example: with port 11436 assigned to odysseus and published as 11436:11436, use http://ubuntu-ai:11436 in Odysseus. Responses stream back on that same connection. No second proxy is needed.

        

        

          
Pause schedules

          

          
Schedules use local time and a fixed end time. Days refer to the starting day for overnight windows. Repeated daylight-saving hours follow the same rule twice; missing local minutes are skipped. Active requests finish. Overlapping pauses combine; ending a schedule never clears a manual pause or recovery lock.

          

          

          
          
Disable a schedule to retire it. Pause stops selected inference only. Release GPU requires all sources/all traffic and drains then unloads Ollama. Frigate discovery and saved-description checks continue. Next transitions appear on the dashboard after applying.

Ollama-only recovery
Host telemetry & automatic recovery
Host helper required

          
Install the host helper and mount its private socket before enabling these settings. The browser cannot install it or change the socket path. Recovery may restart only Ollama within bounded limits; it never resets the GPU or reboots ubuntu-ai. All clients should send inference through this intermediary.

          
One-time setup: pause inference, then run python3 integrations/host/install.py from the updated repository on your Ollama VM as your normal Docker user. The script checks the VM, backs up and merges configuration, and asks for confirmation before sudo. This helper is custom intermediary code, not an AMD service. Disabled monitoring does not check installation; a missing socket can mean either missing host setup or a missing container mount.

Host RAM safeguards

          
Requires the updated host helper. This defers background catch-up, not live Odysseus/Frigate requests, when RAM is low, stale, or under sustained pressure. Pending jobs are kept. Larger-context rescue always requires RAM checks. These are minimum headroom thresholds, not predictions of peak allocation. Fix VM memory allocation and Ollama cache budgets as well.
